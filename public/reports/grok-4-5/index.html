82/100

A strong, honest Phase 1 recreation. The complete six-section deck renders in the correct spec order (performance/organ/piano/program/synth/effects) with exact fractions, a 54/46 deck/keybed split, aspect ratio 3.0951, and an exact 73-key E1-E7 keybed; spec colors are matched precisely and Program/Synth are the only primary OLEDs, with no invented displays or marketing hero. All four gates pass first-hand (32/32 tests, typecheck, lint, build). Main gaps: the narrow 390x844 view retains everything but via heavy compression with truncated labels; audio tests assert only against a mock AudioContext rather than a real signal/analyser; and control micro-layout is a simplified flow approximation, not photo-matched to the dense reference.

What worked

  • Unified playable inputsAll four input paths route through the single PianoEngine lifecycle: Keybed.tsx pointer with Y-derived velocity and per-pointerId independent multi-touch; input/keyboard.ts mapped computer keys with repeat suppression; input/midi.ts note-on/off, velocity, and CC64 sustain.
  • Control movement and feedbackControlWidget.tsx implements pointer-drag AND keyboard operation for every control kind: knob/encoder (role=slider, ArrowUp/Down/Left/Right/Home/End, rotation transform), fader/drawbar (vertical drag + arrows, drawbar inverted), wheel, and pitch stick (horizontal drag, spring-return to 0.5 on release); buttons are native <button> with Enter/Space handling.
  • Decorative-control boundaryArchitectural separation: ControlWidget.tsx only calls hardware-store setValue/pressButton (presentation state); it never imports or touches PianoEngine. Only Keybed/keyboard/MIDI paths reach the engine.
  • Runtime qualityAll four gates pass first-hand: pnpm test 32/32, tsc --noEmit clean, oxlint clean, and build emits dist/index.html with relative ./assets/ paths (base './'); matches verification.json (all checks passed, digest sealed).

Priority issues

  1. Narrow 390x844 layout retains the full surface only via heavy compression / horizontal pan; section titles and control labels truncate with ellipsis (e.g. 'PERFORMAN CONTROLS', 'FX Focus Or...'), hurting legibility rather than reflowing.
  2. Audio behavior is tested exclusively against a mock AudioContext (voice counts, oscillator.started); no real Web Audio signal/analyser assertion that output differs from silence or that velocity/release move output in the expected direction, which the phase's audio test rules request.
  3. Black-key horizontal placement uses a uniform 0.65 white-key offset; the musically-correct per-pitch-class blackOffsets table in Keybed.tsx is computed and then discarded via `void offset`, so black keys are not at true intra-octave positions.
  4. PianoEngine.getActiveNotes() reports velocity: 0 for every active voice (cosmetic; the envelope itself is velocity-scaled correctly).
  5. Control micro-layout is a simplified flow approximation, not pixel-matched to the reference photo, and is noticeably less dense than the real instrument.
