  • Farf's binary drawbar quantisation makes its 9 drawbars behave as 9 switches, so 'drawbars driving the audible spectrum per model' is only partly honoured for that engine.
Synth system 3/4 75
  • Measured in the rendered DOM: all 14 required waveforms are selectable (Sine…FM 2-op (algorithm A)), filter types LP12/LP24/HP/BP with tracking and drive selects, three separate envelopes (oscEnv, filterEnv, ampEnv) each with attack/decay/release/amount and a velocity toggle, LFO with 5 waves / 4 targets / sync, unison, vibrato Off/On/Wheel, voice mode Poly/Mono/Legato with priority and glide, and an arpeggiator with rate, sync, range 1-4, 4 directions, hold and run.
  • Behaviour is real, not cosmetic: startOther() builds different oscillator topologies per waveform category (FM carrier+modulator with depth = ctrl*freq*3, sync pair at freq*(1.05+ctrl*2), 3- or 5-voice detune stacks scaled by oscCtrl), Osc Ctrl therefore does a category-appropriate job; the arp is driven by arpStep() with a deterministic pseudo-random branch and clock-synced interval 60000/tempo/(1+rate*3).
  • Simplifications: all three envelopes are one-shot attack->decay ramps with no sustain stage (ampEnv release is applied at note-off only), and glide only engages in Mono/Legato; mono/legato priority is implemented by scanning active presses rather than a true last/low/high stack.
  • Panel reach is incomplete: the chassis exposes only Synth Layer A and B buttons, so Synth layer C is reachable only from the HTML console below the instrument.
Layers, splits, scenes & morphs 3/4 75
  • Seven layers exist with full per-layer routing — enable, focus, level, octave and zone start/end for Piano:A/B, Organ:A/B and Synth:A/B/C, plus per-layer effect chains and an effects Layer Focus Piano/Organ/Synth trio on the panel.
  • Scenes behave as specified: clicking Scene II on build/ switched the OLED to 'SCENE II' and lit the panel Layer Scene 2 LED (aria-pressed true, LED rgb(252,98,46)); commitStage() records only layer enable flags into scenes[] and never duplicates sound parameters.
  • Morphs interpolate and are stored per source: morphed() adds (to-from)*amount independently for Wheel and Control Pedal and clamps to [0,1]; an assignment made from the panel appeared in the stored program as {from:0.65,to:0.2}.
  • Weaknesses: there is no on-panel morph indicator showing which destinations are assigned, the morph latch is ignored by the console controls, and panel knob positions do not move when a morph or a program recall changes the underlying value.
Programs & Live Mode 3/4 75
  • 32 slots in 4 pages of 8 plus 8 Live slots, all verified in localStorage ('stage4-programs-v3' -> slots.length 32, live.length 8); Page Left/Right, the eight program buttons, the program dial, and Previous/Next all select programs and the selected program button's LED follows (program-4 read aria-pressed true, LED rgb(252,98,46)).
  • Store, Store As with a name field and a destination-audition step, and the 8 auto-storing Live slots all work as driven above; Live slot contents survived a reload.
  • The 'numeric list view' required by programs.navigation is implemented as a bare <select aria-label="Numeric program list"> with 32 options (src/App.tsx:366) rather than a list on the instrument's own display — functional and accessible, but not what the panel shows on the hardware.
