Phase 1

Complete surface and basic piano

Audio strategy
Live synthesis only. One piano-like voice is generated in JavaScript from an additive partial bank with per-partial inharmonicity, per-partial decay, a deterministic hammer transient and a per-note release curve. The rendered samples are written into an AudioBuffer and played through Web Audio (source -> voice gain -> master gain -> destination). No recorded audio is loaded, bundled, fetched or streamed anywhere in this project.
Generated sound sources
  • Modelled piano voice — Deterministic additive synthesis: up to 24 stretched partials per note (inharmonicity 0.00022 + 0.00085 * register), amplitudes tilted by 1/n^0.95 and rolled off by exp(-(n-1) * (1.05 - 0.98 * velocity)), plus a 14 ms deterministic noise burst shaped by the same velocity. Velocity changes both level (0.84 * v^1.25) and spectrum, so a hard stroke is brighter rather than merely louder.

Notes
  • The Program display labels the voice 'Modelled piano' so the interface never implies a recorded grand.
  • No sample set is used for any type, so the piano.json requirement for recorded Grand/Upright/Electric sets is out of Phase 1 scope and is not claimed here.
  • Polyphony is capped at 16 voices with deterministic oldest-first stealing; both the cap and the stealing order are covered by tests.
  • Sustain is a real lifecycle state: released notes are held while the pedal is down and damped when it lifts.
  • Master path: every voice connects through one master gain node at 0.72 fixed gain, then to destination. Nothing bypasses it.
  • Release is a scheduled gain curve (1 -> 0 over 0.46 to 0.18 s depending on register), applied to the voice's own gain node; the source is stopped just after the curve completes.
  • Velocity-0 strikes render silence rather than a very quiet note.
  • The engine reports its real state (idle / loading / ready / suspended / error / fallback) and the Program display prints it verbatim. A browser without Web Audio gets a 'NO AUDIO OUTPUT' fallback in which the keybed still responds but is honestly silent.
Phase 2

Piano library and working effects

Audio strategy
Hybrid, and declared per type. Grand, Upright and Electric play bundled *recordings* (three separate licensed sample sets, shipped inside the build and loaded from the bundle with no network at runtime). Clav, Digital and Misc are *modelled*: they are generated in JavaScript from the additive partial bank in src/audio/pianoModel.ts, with per-model character applied in src/audio/pianoVoice.ts. Every voice — sampled or modelled — then runs through the same layer effect chain, layer level, master gain, limiter and single destination.
Generated sound sources
  • Modelled piano body (Grand/Upright/Electric asset-failure fallback) — Deterministic additive synthesis used only when a recorded set fails to load. Up to 24 stretched partials with per-partial inharmonicity and decay, a deterministic hammer transient, velocity-dependent brightness, and a per-note damper release. This is never presented as a recording: the display reports 'Piano not found' and the library status reports state=fallback.
  • Clav (modelled) — The additive model with a clavinet character: a fast exponential decay and an added third-harmonic transient for the plucked bite. Declared 'modelled' in the model catalogue and printed as 'Clav D6 (modelled)' in the display.
  • Digital (modelled) — The additive model with a clean digital-piano character: a gentle high roll-off, a slightly longer sustain and no hammer noise.
  • Misc mallet (modelled) — The additive model with a marimba/vibraphone character: a hard fast decay plus strong 4x and 7x partials.
  • Reverb impulse responses — Six generated impulse responses (Room, Booth, Spring, Stage, Hall, Cathedral) built from a deterministic PRNG: a pre-delay, early reflections and an exponential noise tail whose length comes from the type's declared decay. Spring additionally has five dispersive taps. No recorded IRs are used.
  • Amp / cabinet / drive curves — A fixed tanh soft-clip transfer curve shared by every saturator (drive is applied as input gain), plus a transparent-below-the-knee output ceiling curve. The Twin, JC and Small models are documented approximations built from a tone stack and cabinet corner frequencies, not measured impulse responses.
