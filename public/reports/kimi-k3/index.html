Priority issues

  1. Startup freeze from O(n·k) reverb impulse render (manually fixed post-seal): The sealed artifact froze the browser main thread for ~13-16s on every load, and again on any reverb type/bright change. web-audio-backend.ts buildImpulse() rendered the convolution IR by running a unit impulse through createReverb().process(), whose direct-form convolution is O(n·k): at 48kHz that is ~172,800 samples against a ~144,000-sample IR, ~2.5e10 multiply-adds. Measured: 4 rendered frames in 16s (a 16,068ms gap with no frames) and 10/10 fresh loads failed to produce a paint within 6s; CPU profile showed 98.9% of samples in the reverb process() function. Phase 1 was unaffected (no reverb). This was fixed manually after sealing so the artifact could be published and played in the gallery: buildImpulse now assembles the buffer directly from the reverb's cached impulse response in O(n), since convolving a unit impulse with h yields h. The fix is output-identical (verified to <1e-7 across all reverb types x bright/dark) and the artifact's own suites still pass (stage2 138/138, stage3 232/232). Post-fix: 480 frames/4s, no gaps, 10/10 loads paint in 33-45ms. A 25-point deduction is applied to this phase because the delivered artifact was unusable as shipped and required manual repair.
  2. Rotary effect is inaudible in the shipped browser instrument. src/audio/web-audio-backend.ts withoutLiveUnits() sets clone.rotary.on=false before per-voice rendering and the backend creates no live rotary node; createRotary() is used only in the deterministic src/audio/render.ts (the path the tests exercise). The comment 'reverb + rotary stay live nodes' is inaccurate. Rotary DSP, acceleration, stop, and To-Rotary/ORGAN routing are correct and tested in-engine but produce no audible output in the browser. Controls still write canonical state, so it is not fabricated success, but a claimed audible effect is not connected to the live signal graph.
  3. Per-voice buffer pre-rendering (8 s) means manual knob turns (filter cutoff, mod/delay/amp/comp) do not re-modulate an already-held note in the browser; only subsequent notes reflect the change. LFO/vibrato/arp are baked into the buffer so they still animate. A reasonable engineering tradeoff, honestly non-faking, but it limits live expressive real-time automation on sustained notes.
  4. Grand/Upright/Electric ship as 108 bundled WAV takes (verified on disk under public/samples/) but are locally rendered from the project's own physical models via scripts/render-samples.mjs rather than acoustic recordings. IMPLEMENTATION_DETAILS.json declares this truthfully (kind: recorded-sample-set, source describes local rendering, CC0) and they are offline-capable and audibly distinct, so this satisfies the honesty contract; noted only for transparency.
